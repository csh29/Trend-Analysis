# admin-screens.md — 관리 화면

사이드바 "관리"(`MENU_GROUP=MNG`)의 프로그램·사용자·사용자별 권한·공통코드 마스터/디테일 관리.
코드: `service/program`·`user`·`permission`·`comcd`, `config/DataInitializer`.

## 규칙

- **역할 등급은 공통코드 `ROLE`의 정렬순서**다(작을수록 높음). 역할 값은 `ROLE` 코드만 쓴다.
- **사용자 관리 제한** — 권한 상승과 "마지막 관리자가 자기를 지워 복구 불가"를 막는다. 편의를 위해 되돌리지 않는다.
  - 자기 자신은 비밀번호만 바꿀 수 있고 삭제할 수 없다.
  - 자신보다 높은 역할의 계정은 저장·삭제할 수 없고, 자신보다 높은 역할을 줄 수도 없다.
- `User`는 반드시 `UserResponse`로 내보낸다(비밀번호 해시).
- 사이드바 그룹은 공통코드 `MENU_GROUP`이 정한다. 기능 그룹은 MNG(99)보다 작은 정렬순서로 넣는다(관리가 맨 아래).
- 프로그램 id = 화면 id = 템플릿 이름.

## 주의점

- **삭제 순서:** 프로그램·사용자를 지우면 딸린 권한 행을, 공통코드 그룹을 지우면 딸린 코드를 먼저 지운다.
- **사용자별 권한 저장은 통째 교체**다. 벌크 DELETE 후 INSERT — 행 단위로 섞으면 (user, program) 유일 제약을 위반한다.
- 공통코드 디테일은 마스터의 자연키(`codeGroup`)를 들고 있다.
- **프로그램이 읽는 목록은 Java에 박지 않고 공통코드에 둔다**(2026-10-22 사용자 결정): 트렌드 분석 화면 유형(`TREND_VALUE_TYPE`), 유행 질문 단어(`RAG_TREND_WORD`), 아이템 종류(`TREND_ITEM`, 코드값 = `카테고리_종류`) 등. 고치면 재기동 없이 다음 분석·질문부터 쓴다.
- **공통코드 속성(`attr1`)**: 비고는 사람이 읽는 설명, 속성은 프로그램이 읽는 값이다. 그룹마다 뜻이 다르고 그룹 비고에 적는다: `TREND_SILHOUETTE` `축,쓸 수 있는 카테고리…`(예: `FIT,OUTER,TOP,DRESS,SETUP`, 카테고리를 안 적으면 전체), `TREND_MATERIAL` IMAGE(사진으로 구분되는 소재), `TREND_CATEGORY` 일상 표현 쉼표 목록, `TREND_VALUE_TYPE` RAG(질문 답변에 참고 집계로 보냄).
- 예전 DB의 속성은 기동 때 기본값으로 맞춘다: **빈 속성은 채우고, 기본값의 앞부분만 있는 속성(예: 축만 있는 `FIT`)은 기본값으로 늘린다.** 화면에서 다르게 고친 값은 건드리지 않는다.
- 사용 안 함으로 바꾼 코드도 과거 데이터(집계 등)에 남아 있다. 이름을 보여 줄 때는 사용 여부와 상관없이 읽는다.

## 기본 데이터 (`DataInitializer`)

- 항목별로 **없을 때만** 넣는다. 화면에서 사람이 고친 값을 덮어쓰지 않는다. 기존 DB에도 들어가야 하는 것은 "사용자 0명"이 아니라 그 항목의 존재로 판단한다.
- 새로 등록한 프로그램은 기존 DB의 `admin`에게 모든 버튼 권한으로 붙는다.
- 다른 기동 작업보다 먼저 돈다(`@Order(HIGHEST_PRECEDENCE)`).
- 초기 관리자를 잃어버렸으면 `backend/data/`를 지우고 다시 띄운다(데이터 초기화).

## 확인할 것

`UserService`를 고치면 비밀번호 미노출·역할 검증·자기 삭제 금지·상위 역할 제한. `DataInitializer`를 고치면 새 DB 기동과 기존 DB 재기동(중복 삽입 없음) 둘 다.
