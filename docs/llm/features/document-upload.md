# document-upload.md — 원문 등록 (이미지 업로드 · 텍스트 등록)

P-01 수집·P-02 전처리 대신 사람이 원문을 넣는 화면. 등록하면 원문 문서(`source_documents`)가 생기고 분석 대기열에 들어간다([`analysis-pipeline.md`](analysis-pipeline.md)).
코드: `service/image/ImageService`·`ImageType`, `service/analysis/DocumentService`·`TextRegistrationService`.

## 결정 사항 (2026-10-20 사용자)

- **출처:** 테스트 단계라 업로드 이미지는 매체 "직접 업로드"·게시일=업로드일·URL=이미지 주소로 대신한다. 텍스트는 입력값, 비우면 "직접 등록"·오늘.
- 목록의 카테고리 칸은 의류 아이템 카테고리를 나온 순서로 잇는다(예: "상의, 하의").
- **원문 1건 = 본문 + 이미지 N장**(2026-10-21 사용자 결정). 기사·잡지·인스타 게시물은 본문과 사진이 한 묶음이다. 따로 등록하면 같은 트렌드가 본문 1번·사진마다 1번씩 세지고, 본문의 소재·시즌이 사진 분석에 반영되지 않는다. 그래서 텍스트 등록에서 이미지를 **최대 5장** 첨부하고, 한 원문으로 저장·분석·집계·색인한다.
  - 이미지 업로드 화면은 본문 없는 원문(출처 없는 사진 등)용으로 남긴다 — 사진 한 장 = 원문 하나(`IMAGE`).
  - 나중에 수집(P-01)을 소스별(기사·잡지·인스타)로 나눠도 저장은 이 구조로 들어온다. 수집 경로를 나누는 것과 본문·이미지를 나누는 것은 다른 문제다.
- 저해상도 이미지를 서버에서 늘려 저장하지 않는다 — 정보가 늘지 않고, AI 업스케일은 질감을 지어내 분석을 오염시키며, 토큰만 는다.

## 규칙

- **이미지 형식은 파일 내용(시그니처)으로 정한다**(jpg·png·gif·webp·bmp). 확장자·Content-Type은 믿지 않는다. SVG는 같은 출처에서 열면 스크립트가 실행되므로 받지 않는다.
- **저장 파일명은 서버가 만든 UUID만** 쓴다. 사용자 파일명은 표시용이고 경로 성분을 지운다(경로 조작·덮어쓰기 방지).
- 한 장이라도 이미지가 아니면 전부 거부하고 파일·DB에 아무것도 남기지 않는다.
- **같은 이미지는 다시 올리지 않는다**(파일 내용 SHA-256, `uploaded_images.content_hash`). 이미 올린 것·같은 요청 안의 중복은 건너뛰고 나머지만 저장하며, 건너뛴 파일과 먼저 올린 파일명을 응답(`duplicates`)으로 알려 준다. 같은 문서가 두 번 집계되고 토큰도 두 번 들던 문제(2026-10-20 DB에서 같은 사진 2건 확인) 때문이다. 해시 칸 이전 이미지는 기동 때 채운다. 그 전에 생긴 중복은 남아 있을 수 있어 유일 제약은 두지 않는다.
- **첨부 이미지:** `uploaded_images.document_id`가 그 텍스트 원문을 가리키고 `sort_order`가 순서다(분석에 보내는 순서). 따로 올린 이미지는 `document_id`가 비고, 원문 쪽 `source_documents.image_id`가 이미지를 가리킨다. 첨부는 이미지 업로드 목록에 나오지 않는다.
  - 등록 순서: 이미지 검증(형식·장수·중복) → 원문 저장 → 첨부 저장 → 분석 대기열. 이미지가 잘못됐으면 원문도 만들지 않고, 첨부 저장이 실패하면 원문을 되돌린다. 분석은 첨부를 다 붙인 뒤에 시작해야 이미지까지 본다.
  - 중복 이미지(이미 올린 것과 같은 파일)는 건너뛰고 원문은 등록한다(`skippedImages`로 알림).
  - 첨부는 텍스트 등록 권한으로 연다(`/api/texts/{id}/images/{imageId}/file`) — 그 원문의 이미지 id만 열린다. 이미지 업로드 화면의 삭제 API로는 첨부를 지우지 못하고, 원문을 지우면 같이 지워진다.
  - API: 본문만이면 JSON, 이미지가 있으면 multipart(`request` = JSON, `files` = 이미지들) — 같은 `POST /api/texts`.
- **같은 원문은 URL로 막는다**(2026-10-22 사용자 결정): 텍스트 원문의 URL을 정규화해 저장하고(`SourceUrls` — http/https·www·끝 `/`·`#`·추적 파라미터 utm_*·fbclid·igshid 등 제거, 남은 파라미터 정렬), 같은 URL이 이미 있으면 400("이미 등록된 원문"). 같은 원문이 두 번 저장되면 유행 집계에서 두 번 세지기 때문이다. 한 매체가 다른 게시물로 여러 번 올린 것은 URL이 달라 막지 않는다 — 유행 집계가 매체 수로 따로 본다. 크롤링(P-01)도 이 규칙으로 저장한다.
- 업로드 크기 상한은 설정(`image.upload.*`)이다. 넘으면 `UploadSizeExceptionAdvice`가 400으로 바꾼다.
- 저장된 원문에는 출처(매체·게시일)가 반드시 있어야 한다 — 없으면 분석하지 않는다(RAG 답변의 근거 표시가 이 값을 쓴다). 입력이 비면 위 기본값으로 채우므로 사용자가 꼭 적어야 하는 것은 아니다.
- 삭제하면 파일·원문 문서·트렌드 항목·색인을 같이 지운다(색인 삭제는 AI 서비스가 꺼져 있어도 진행하는 best-effort).

## 주의점

- **등록은 트랜잭션으로 감싸지 않는다.** 문서 저장이 커밋된 뒤 분석 이벤트를 내야 분석 스레드가 문서를 읽는다.
- 업로드 파일은 `image.upload.dir`(기본 `backend/uploads/images`, git 제외)에 있다.
- 업로드·등록 API 테스트에는 `@MockBean AiClient`를 붙인다. 빼면 실제 127.0.0.1:8001을 부른다.
