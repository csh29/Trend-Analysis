# document-upload.md — 원문 등록 (이미지 업로드 · 텍스트 등록)

P-01 수집·P-02 전처리 대신 사람이 원문을 넣는 화면. 등록하면 원문 문서(`source_documents`)가 생기고 분석 대기열에 들어간다([`analysis-pipeline.md`](analysis-pipeline.md)).
코드: `service/image/ImageService`·`ImageType`, `service/analysis/DocumentService`.

## 결정 사항 (2026-10-20 사용자)

- **출처:** 테스트 단계라 업로드 이미지는 매체 "직접 업로드"·게시일=업로드일·URL=이미지 주소로 대신한다. 텍스트는 입력값, 비우면 "직접 등록"·오늘.
- 목록의 카테고리 칸은 의류 아이템 카테고리를 나온 순서로 잇는다(예: "상의, 하의").
- 저해상도 이미지를 서버에서 늘려 저장하지 않는다 — 정보가 늘지 않고, AI 업스케일은 질감을 지어내 분석을 오염시키며, 토큰만 는다.

## 규칙

- **이미지 형식은 파일 내용(시그니처)으로 정한다**(jpg·png·gif·webp·bmp). 확장자·Content-Type은 믿지 않는다. SVG는 같은 출처에서 열면 스크립트가 실행되므로 받지 않는다.
- **저장 파일명은 서버가 만든 UUID만** 쓴다. 사용자 파일명은 표시용이고 경로 성분을 지운다(경로 조작·덮어쓰기 방지).
- 한 장이라도 이미지가 아니면 전부 거부하고 파일·DB에 아무것도 남기지 않는다.
- **같은 이미지는 다시 올리지 않는다**(파일 내용 SHA-256, `uploaded_images.content_hash`). 이미 올린 것·같은 요청 안의 중복은 건너뛰고 나머지만 저장하며, 건너뛴 파일과 먼저 올린 파일명을 응답(`duplicates`)으로 알려 준다. 같은 문서가 두 번 집계되고 토큰도 두 번 들던 문제(2026-10-20 DB에서 같은 사진 2건 확인) 때문이다. 해시 칸 이전 이미지는 기동 때 채운다. 그 전에 생긴 중복은 남아 있을 수 있어 유일 제약은 두지 않는다.
- 업로드 크기 상한은 설정(`image.upload.*`)이다. 넘으면 `UploadSizeExceptionAdvice`가 400으로 바꾼다.
- 출처(매체·게시일)는 필수다 — 없으면 분석하지 않는다(RAG 답변의 근거 표시가 이 값을 쓴다).
- 삭제하면 파일·원문 문서·트렌드 항목·색인을 같이 지운다(색인 삭제는 AI 서비스가 꺼져 있어도 진행하는 best-effort).

## 주의점

- **등록은 트랜잭션으로 감싸지 않는다.** 문서 저장이 커밋된 뒤 분석 이벤트를 내야 분석 스레드가 문서를 읽는다.
- 업로드 파일은 `image.upload.dir`(기본 `backend/uploads/images`, git 제외)에 있다.
- 업로드·등록 API 테스트에는 `@MockBean AiClient`를 붙인다. 빼면 실제 127.0.0.1:8001을 부른다.
