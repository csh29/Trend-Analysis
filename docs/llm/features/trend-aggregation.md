# trend-aggregation.md — P-05 트렌드 집계

분석이 끝난 문서의 트렌드 항목을 주 단위로 세어 언급량·증감률·급상승을 낸다. 화면은 "트렌드 분석"(`trend-analysis`).
코드: `service/trend`(`TrendAggregator` 계산, `TrendAggregationService` 배치·주 마감, `TrendQueryService` 조회), 표 `trend_weekly_stats`·`trend_week_closes`·`trend_week_close_docs`·`trend_week_close_logs`.

## 결정 사항 (사용자)

- **급상승:** 전주 대비 **+20% 이상**(`trend.surge.rate`, 기본 20). 최소 건수 `trend.surge.min-count`(기본 1)는 따로 정하지 않았다 — 1건→2건도 +100%로 급상승이 된다.
  - 다시 정하는 조건(제안값): 최근 4주 연속 주마다 분석 완료 원문이 20건 이상 들어오거나(크롤링 P-01 가동 등), 화면 급상승 목록의 절반 이상이 이번 주 2건 이하 값이면 사용자에게 최소 건수(제안 3건)와 비율을 다시 묻는다.
- **집계 날짜:** 원문 게시일, 없으면 업로드(등록)일.
- **주 마감(2026-10-30, ERP 마감처럼):** 마감한 주는 다시 집계하지 않는다.
  - 자동 + 수동: 매주 월요일 새벽(`trend.close.cron`, 기본 `0 30 3 * * MON`) 지난주까지 자동 마감(`trend.close.auto`, 기본 true — 그때 앱이 꺼져 있었으면 기동할 때 따라잡는다). 화면 "마감"(기타2)으로 먼저 마감할 수도 있다.
  - 마감 취소는 "마감 취소"(기타3) 권한자만, 사유 필수, **가장 최근 마감 주부터 하나씩**. 취소한 주는 다시 열린 주가 되어 원문에서 다시 센다.
  - 늦게 온 원문(게시일이 마감된 주): **첫 열린 주에 센다**(ERP 당기 처리). 게시일은 그대로, 센 주만 다르다(근거 원문의 "센 주").
  - 권한: 마감·마감 취소는 트렌드 분석 버튼 권한(기타2·기타3)이다. admin은 등록 때 모든 버튼을 받았고, 다른 사용자는 사용자별 권한관리에서 준다. 서버도 버튼 권한을 확인한다(`ProgramAccessGuard.requireButton` — 툴바 숨김만으로는 API를 못 막는다).

## 규칙

- 언급량은 **문서 수**다. 한 문서에 같은 값이 여러 번 나와도 1. 분석 완료(DONE) 문서만 센다.
- 주는 월~일. 전주가 0이면 증감률을 계산하지 않고 **신규**로 표시한다(급상승에 넣지 않는다).
- 전월 대비는 직전 4주 **평균**과 비교한다(4주 전 한 주와 비교하면 그 주 사정에 너무 흔들린다).
- 카테고리 범위는 전체(`ALL`)와 카테고리별로 미리 세어 둔다. **소재·컬러·실루엣·패턴·디테일은 그 의류 아이템의 카테고리로** 센다 — 코디 사진의 상의 그레이가 하의 컬러로 잡히지 않게. 키워드는 문서 단위라 문서에 나온 아이템 카테고리마다 센다. 카테고리 자체의 언급량(`CATEGORY`)은 전체에만 있고, 한 문서가 상의·하의 양쪽에 잡힌다.
- 시즌(`SEASON`)은 키워드처럼 문서 단위로 센다. 트렌드 분석 화면의 조회 조건은 유형·카테고리·기준 주·기간뿐이라 시즌으로 거르지 않는다 — 시즌은 유형 `SEASON`으로 본다(챗봇은 원문 시즌 값으로 거른다, [`rag-search.md`](rag-search.md)).
- 유형에 **아이템 종류**(`ITEM_TYPE`, 공통코드 `TREND_ITEM` — 패딩·블루종…)가 있다. **아이템명(`ITEM`)은 유형이 아니다**(사용자 결정 — 종류와 뜻이 겹쳐 헷갈린다): 주간 집계에서 세지 않고, 기존 DB의 유형 코드와 지난 집계 줄은 기동 때 지운다(`DataInitializer`). 아이템명이 쓰이는 곳(색인·챗봇 유행 집계)은 [`analysis-pipeline.md`](analysis-pipeline.md). 유형 목록·이름은 공통코드 `TREND_VALUE_TYPE`(화면 select)이다.
- 홈 챗봇의 유행 질문은 이 주간 표가 아니라 질문할 때 원문을 바로 센다(주 마감과 상관없다)([`rag-search.md`](rag-search.md) — 원문 수·매체 수, 방금 올린 원문도 반영).
- 키워드는 LLM이 쓴 문자열이라 공백만 맞춰 센다. "레더 재킷"과 "가죽 재킷"은 다른 값이다 — 소재·컬러·실루엣(공통코드)이 더 믿을 만한 지표다.
- 화면 기본 기준 주는 **지난주**다. 이번 주는 진행 중이라 전주보다 작게 나와 감소로 보인다.

## 배치

- **열린 주만** 다시 만든다(마지막 마감 주 다음 주부터 삭제 후 삽입). 열린 주의 전주·4주 평균은 마감된 주의 확정 언급량(집계 행)을 쓴다. 마감이 없으면 전부 다시 만든다. 집계·마감·취소는 한 번에 하나만 돈다(락).
- 마감은 오래된 주부터 이어진다 — "X주까지 마감"이면 그 앞의 열린 주도 같이 마감한다(마감이 처음이면 첫 원문 주부터). 이번 주(진행 중)는 마감할 수 없다. 마감 직전에 열린 주를 한 번 더 집계하고, 그 주에 센 원문을 `trend_week_close_docs`에 고정한다(원문 하나는 한 주에만).
- 마감된 주의 원문을 재분석·삭제해도 그 주 수치는 바뀌지 않는다(마감 당시 그대로). 근거 원문은 마감 때 고정한 원문 중 지금도 그 값이 있는 것만 보인다.
- 원문의 집계 주(`TrendAggregationService.WeekAssignment`): 고정된 원문은 그 주, 나머지는 집계 날짜의 주와 첫 열린 주 중 늦은 쪽. 근거 원문 조회도 같은 기준이다.
- 화면 "집계"는 보고 있는 기준 주를 같이 보내고, 그 주가 마감됐으면 거부한다(400 — 마감된 주를 보며 눌러도 "집계했습니다"가 떠 헷갈렸다). 열린 주를 보고 있으면 열린 주 전체를 다시 센다.
- 마감 이력(`trend_week_close_logs`)은 지우지 않는다 — 마감·취소, 처리자(자동이면 SYSTEM), 취소 사유.
- 도는 때: 매일 `trend.aggregate.cron`(기본 새벽 3시), 기동 직후, 화면의 "집계" 버튼. **분석이 끝났다고 자동으로 다시 집계하지 않는다** — 바로 보려면 "집계"를 누른다.
- DONE 문서 전부를 메모리에 올려 센다. 배치 한 번이 1분을 넘거나(로그 "트렌드 집계 완료 … ms") DONE 문서가 1만 건을 넘으면(제안값) DB 집계 쿼리로 바꾼다.

## 샘플 데이터

```bash
java -jar target/trend-analysis-0.0.1-SNAPSHOT.jar --trend.sample.load=true
```

- `resources/sample/trend-sample-texts.json`의 텍스트 37건을 "기동한 날 기준 몇 주 전"으로 넣는다(레더·니트 상승, 숏패딩 신규, 데님 유지, 린넨 하락).
- 제목이 `[샘플]`로 시작하는 문서가 있으면 다시 넣지 않는다. 지우려면 텍스트 등록 화면에서 지운다.
- 실제 Claude 분석을 거친다(37건 호출). `DataInitializer`보다 늦게 돌아야 한다(`@Order`) — 먼저 돌면 표준 코드가 없어 전부 실패한다.

## 테스트

- `TrendAggregatorTest`(순수): +20% 경계, 신규, 사라진 값(-100%), 4주 평균, 문서당 1건·카테고리 범위, 최소 건수, 마감된 주 확정값으로 전주·4주 평균.
- `TrendCloseApiTest`: 마감(앞 주 같이)·이미 마감·이번 주 거부 → 늦게 온 원문은 첫 열린 주 → 근거 원문의 센 주 → 마감 취소(사유 필수) → 다시 집계, 권한 403.
- 테스트 설정은 `trend.close.auto=false` — 기동 때 자동 마감하면 고정 날짜로 나중에 넣는 원문이 전부 "늦게 온 원문"이 된다.
- `TrendApiTest`: 집계 → 조회(라벨은 공통코드 이름) → 근거 원문, 실패 문서 제외, 권한 403. 기준 주는 고정 날짜라 실행 날짜와 무관하다.
- `SampleDataLoaderTest`: 최근 6주 날짜·한 번만 넣기·공통코드 시드 뒤에 분석.
- 화면 확인은 Claude 없이 할 수 있다: 정해진 규칙으로 답하는 가짜 AI 서버를 `ai.server.url`로 물리고 `--trend.sample.load=true`로 띄운다. 가짜 서버는 chunked 요청 본문을 읽어야 한다(Spring이 Content-Length 없이 보낸다).
