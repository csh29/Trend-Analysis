# trend-aggregation.md — P-05 트렌드 집계

분석이 끝난 문서의 트렌드 항목을 주 단위로 세어 언급량·증감률·급상승을 낸다. 화면은 "트렌드 분석"(`trend-analysis`).
코드: `service/trend`(`TrendAggregator` 계산, `TrendAggregationService` 배치, `TrendQueryService` 조회), 표 `trend_weekly_stats`.

## 결정 사항 (2026-10-20 사용자)

- **급상승:** 전주 대비 **+20% 이상**(`trend.surge.rate`, 기본 20). 최소 건수 `trend.surge.min-count`(기본 1)는 따로 정하지 않았다 — 1건→2건도 +100%로 급상승이 된다. 크롤링(P-01)으로 주마다 원문이 꾸준히 들어오기 시작하면, 또는 급상승 목록이 1~2건짜리로 채워진다는 말이 나오면 사용자에게 기준을 다시 묻는다.
- **집계 날짜:** 원문 게시일, 없으면 업로드(등록)일.

## 규칙

- 언급량은 **문서 수**다. 한 문서에 같은 값이 여러 번 나와도 1. 분석 완료(DONE) 문서만 센다.
- 주는 월~일. 전주가 0이면 증감률을 계산하지 않고 **신규**로 표시한다(급상승에 넣지 않는다).
- 전월 대비는 직전 4주 **평균**과 비교한다(4주 전 한 주와 비교하면 그 주 사정에 너무 흔들린다).
- 카테고리 범위는 전체(`ALL`)와 카테고리별로 미리 세어 둔다. **소재·컬러·실루엣은 그 의류 아이템의 카테고리로** 센다 — 코디 사진의 상의 그레이가 하의 컬러로 잡히지 않게. 키워드는 문서 단위라 문서에 나온 아이템 카테고리마다 센다. 카테고리 자체의 언급량(`CATEGORY`)은 전체에만 있고, 한 문서가 상의·하의 양쪽에 잡힌다.
- 시즌(`SEASON`)은 키워드처럼 문서 단위로 센다. 시즌으로 거르는 필터는 아직 없다(유형으로만 본다).
- 유형에 **아이템 종류**(`ITEM_TYPE`, 공통코드 `TREND_ITEM` — 패딩·블루종…)가 있다. **아이템명(`ITEM`)은 유형이 아니다**(2026-10-23 사용자 결정 — 종류와 뜻이 겹쳐 헷갈린다): 세지 않고, 기존 DB의 유형 코드와 지난 집계 줄은 기동 때 지운다(`DataInitializer`). 아이템명은 챗봇의 기타 종류 설명에만 쓴다. 유형 목록·이름은 공통코드 `TREND_VALUE_TYPE`(화면 select)이다.
- 홈 챗봇의 유행 질문은 이 주간 표가 아니라 질문할 때 원문을 바로 센다([`rag-search.md`](rag-search.md) — 원문 수·매체 수, 방금 올린 원문도 반영).
- 키워드는 LLM이 쓴 문자열이라 공백만 맞춰 센다. "레더 재킷"과 "가죽 재킷"은 다른 값이다 — 소재·컬러·실루엣(공통코드)이 더 믿을 만한 지표다.
- 화면 기본 기준 주는 **지난주**다. 이번 주는 진행 중이라 전주보다 작게 나와 감소로 보인다.

## 배치

- 표를 **통째로 다시 만든다**(삭제 후 삽입). 재분석·삭제로 과거 주 값이 바뀌어도 따로 추적하지 않기 위해서다. 한 번에 하나만 돈다(락).
- 도는 때: 매일 `trend.aggregate.cron`(기본 새벽 3시), 기동 직후, 화면의 "집계" 버튼. **분석이 끝났다고 자동으로 다시 집계하지 않는다** — 바로 보려면 "집계"를 누른다.
- 지금은 DONE 문서 전부를 메모리에 올려 센다. 문서가 수만 건이 되면 DB 집계 쿼리로 바꾼다.

## 샘플 데이터

```bash
java -jar target/trend-analysis-0.0.1-SNAPSHOT.jar --trend.sample.load=true
```

- `resources/sample/trend-sample-texts.json`의 텍스트 37건을 "기동한 날 기준 몇 주 전"으로 넣는다(레더·니트 상승, 숏패딩 신규, 데님 유지, 린넨 하락).
- 제목이 `[샘플]`로 시작하는 문서가 있으면 다시 넣지 않는다. 지우려면 텍스트 등록 화면에서 지운다.
- 실제 Claude 분석을 거친다(37건 호출). `DataInitializer`보다 늦게 돌아야 한다(`@Order`) — 먼저 돌면 표준 코드가 없어 전부 실패한다.

## 테스트

- `TrendAggregatorTest`(순수): +20% 경계, 신규, 사라진 값(-100%), 4주 평균, 문서당 1건·카테고리 범위, 최소 건수.
- `TrendApiTest`: 집계 → 조회(라벨은 공통코드 이름) → 근거 원문, 실패 문서 제외, 권한 403. 기준 주는 고정 날짜라 실행 날짜와 무관하다.
- `SampleDataLoaderTest`: 최근 6주 날짜·한 번만 넣기·공통코드 시드 뒤에 분석.
- 화면 확인은 Claude 없이 할 수 있다: 정해진 규칙으로 답하는 가짜 AI 서버를 `ai.server.url`로 물리고 `--trend.sample.load=true`로 띄운다. 가짜 서버는 chunked 요청 본문을 읽어야 한다(Spring이 Content-Length 없이 보낸다).
